# Jesús A. Moreno López: personal website

Live at **https://jeslop013.github.io** (once published).
Built with [Astro](https://astro.build): every page is generated from plain text files in this folder.

---

## The big picture

```
 1. EDIT           2. PREVIEW ON YOUR PC         3. SAVE (commit)        4. PUBLISH (push)
 change files  →   http://localhost:4321     →   git commit          →   git push
                   (only you can see it)         (a snapshot, still      (GitHub rebuilds the site;
                                                  only on your PC)        live in ~1–2 minutes)
```

**Nothing goes online until step 4.** You can edit, preview and break things as much as you like.

## Step 2: Preview your changes locally

### Live preview (use this while editing)

```
npm run dev
```

Then open **http://localhost:4321** in your browser.

- Leave it running. Every time you save a file, the page in the browser updates by itself.
- Posts marked `draft: true` are hidden here too. Set it to `false` to preview them.
- To stop the preview: click in the terminal and press **Ctrl + C**.

### Final check (do this before publishing)

The live preview is forgiving. This builds the site **exactly as it will be published**:

```
npm run build
npm run preview
```

- If `npm run build` prints an **error**, fix it before publishing (or paste it to Claude).
  A broken build will not go online, but your update won't appear either.
- `npm run preview` then serves that final version at **http://localhost:4321**. Click through
  the pages. Stop with **Ctrl + C**.

## Steps 3 & 4: Save and publish

```
git status                         # see which files you changed
git add -A                         # include all changes
git commit -m "Add post on X"      # save a snapshot with a short description
git push                           # send it to GitHub → the site rebuilds and goes live
```

After `git push`, watch the progress at
**https://github.com/jeslop013/jeslop013.github.io/actions**: a green tick ✅ means it's live,
a red cross ❌ means the build failed (the old version stays online; open it to see why).

### Undoing things

| Situation | Command |
|---|---|
| Throw away unsaved edits to one file | `git restore path/to/file` |
| Throw away **all** edits since the last commit | `git restore .` |
| See the history of snapshots | `git log --oneline` |
| Undo a published change | Ask Claude. `git revert` makes a new commit that cancels an old one. |

## Writing a post

Create a new file, e.g. `src/content/science/2026-12-01-my-post.md`:

```markdown
---
title: My new post
date: 2026-12-01
description: One sentence that appears in the list.
tags: [epidemics, networks]
draft: true         # hidden while you work on it; change to false to publish
---

Normal text, **bold**, *italic*, [links](https://example.com).

Inline maths $R_0 > 1$ and display maths:

$$ \frac{dI}{dt} = \beta S I - \gamma I $$

![A figure](/figures/my-figure.png)
```

- The file name becomes the web address: `…/science/2026-12-01-my-post/`.
- **Spanish version:** put a file with the same name in `src/content/science/es/`. The post page then shows an English | Español switch, and the Science list has a language filter.
- **Variety:** add `short: true` to show the full text directly in the Variety list (no separate page click).
- **Projects end by themselves:** in `src/data/cv.ts`, give a project an `end` year. After that year it moves from *Current* to *Past* on the next build.
- Images go in `public/` (e.g. `public/figures/my-figure.png` → write `/figures/my-figure.png`).
- Typical loop: write with `draft: false` → check it at http://localhost:4321/science/ → commit → push.

### Using a real figure instead of a schematic

Put the image in `public/figures/`, then in `src/pages/index.astro` (Research themes) pass it as
`<ProjectFigure name={t.figure} image="/figures/your-image.png" alt="…" />` (or ask Claude).

## How publishing works (for reference)

- The code lives in the GitHub repository `jeslop013/jeslop013.github.io`.
- `.github/workflows/deploy.yml` tells GitHub: *on every push to `main`, build the site and publish it*.
- GitHub Pages setting: repository **Settings → Pages → Source: GitHub Actions**.
- To use a custom domain later: buy it, add it under Settings → Pages, and update `site` in `astro.config.mjs`.
